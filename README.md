# tier0.dll — реконструкция системной DLL движка GoldSrc

> **Это репозиторий-модификация.** Здесь лежит улучшенная сборка `tier0.dll`:
> полностью совместимая с оригиналом (313/313 экспортов, те же ординалы),
> но с работой «под капотом» (см. раздел «Внутренние улучшения»).
>
> Скачивайте осознанно:
>
> - **нужна версия как у оригинала** — берите релиз **v1.0.0** (тег `v1.0.0`);
> - **нужна улучшенная модификация** — берите последний релиз (v1.1.0+).

Функциональная реконструкция `tier0.dll` из движка **GoldSrc**, написанная
с нуля по дизассемблеру оригинальной сборки и собранная на современном MSVC.

DLL воспроизводит **все 313 экспортов оригинала с точными ординалами (1–313)**
и имеет тот же image base (`0x10000000`). `tier0.dll` — низший уровень системы:
её используют `chromehtml.dll`, `vstdlib.dll`, движок и моды. Без неё игра
не запускается.

---

## Для каких игр

- **Counter-Strike 1.6** — `hl.exe -game cstrike`
- **Half-Life** — `hl.exe`
- **Day of Defeat** — `hl.exe -game dod`
- **Team Fortress Classic** — `hl.exe -game tfc`
- любые моды на GoldSrc

Требуется **32-битный Steam-клиент**: Steam, по умолчанию, ставит его при
установке этих игр (совместимость с SteamPipe/SteamPipe-only окружениями — как
у оригинала).

## С какого билда снят оригинал

Оригинал взят из текущей Steam-установки **Counter-Strike 1.6** — это
**последний официальный билд движка**:

- движок: билд **10210** («25th Anniversary Update»), строка `Exe build:
  19:06:31 Oct 7 2024`;
- протокол **48**, `hl.exe` 1.1.1.1;
- эталонный `tier0.dll`: `TimeDateStamp 2024-10-08 01:54:33 UTC`;
- бинари движка не перекомпилировались с октября 2024 (анонсирован был апдейт
  декабря 2023, билд же 10210 Valve выложил молча, без новостного поста).

## Структура проекта

```
tier0/
├── build.bat            Сборка DLL (авто-детект toolchain)
├── tier0.def            Файл экспортов: 313 имён в порядке ординалов 1..313
├── tier0/               Исходники библиотеки (C++ + один .asm)
│   ├── tier0.cpp        Точка входа, стек-трейсы, обработчики FPU/катастроф
│   ├── dbg.cpp          Spew-система, ассерты, валидация указателей
│   ├── mem.cpp          IMemAlloc / менеджер памяти
│   ├── threadtools.cpp  Потоки, события, мьютексы, worker-пул
│   ├── vprof.cpp        Профилировщик (дерево узлов, бюджет-группы)
│   ├── cpu.cpp          Определение CPU (CPUID: MMX/SSE/SSE2/SSE3/AVX, ядра)
│   ├── platform.cpp     Платформозависимые функции (Plat_*)
│   ├── minidump.cpp     Создание .mdmp при крашах
│   ├── ...              Остальные модули (validator, valobject, shims...)
│   └── fdumped_asm_exact.asm  Ассемблерный фрагмент, дословно воспроизведённый по оригиналу
├── tests/              Функциональные проверки DLL (vprof-харнесс, allocator-тест, бенч хот-путей, сверка 313 экспортов — см. tests/README.md)
└── public/tier0/        Публичные заголовки (dbg.h, threadtools.h, vprof.h, ...)
```

Сборка выдаёт единственный артефакт — `build/tier0.dll` (~64 КБ).

## Сборка

### Требования

- Windows x64 или x86;
- **Visual Studio Build Tools** (или полная VS) с компонентом
  «Desktop development with C++», включая инструменты сборки **x86**;
- достаточно любой свежей версии: 2019, 2022 и новее. Собиралось и проверялось
  на: **VS 18 Build Tools**, **MSVC 14.51.36231** (v143), **Windows SDK
  10.0.26100**;
- ничего стороннего (CMake, Qt и т.п.) не нужно.

### Проще всего

```
build.bat
```

Скрипт сам находит `vcvars32.bat` (пробует VS 18 → 2022 → 2019), настраивает
окружение и собирает DLL. Результат:

```
BUILD OK: ...\build\tier0.dll
```

Если уже открыт «x86 Native Tools Command Prompt», скрипт использует его
окружение и не ищет toolchain заново.

### Что делает `build.bat`

1. определение toolchain (`VCToolsInstallDir` либо поиск `vcvars32.bat`);
2. сборка `fdumped_asm_exact.asm` через `ml`;
3. компиляция всех `tier0\*.cpp` через `cl` (x86);
4. линковка: `link /DLL /DEF:tier0.def /BASE:0x10000000 /MACHINE:X86`
   (библиотеки: kernel32, user32, advapi32, dbghelp, odbc32).

## Установка

Положить `build\tier0.dll` рядом с `hl.exe`, например:

```
D:\SteamLibrary\steamapps\common\Half-Life\tier0.dll
```

Проверено на CS 1.6: `hl.exe -game cstrike` загружается и работает стабильно,
`crash.log` не создаётся, профилирование `-vprof` работает. Дополнительно
прогнан смоук на Dedicated Server (`hlds.exe`, билд 10210, `cstrike` 1.1.2.7):
сервер поднимается и работает с этой DLL без крашей; полный игровой прогон
описан в истории релизов.

## Важно: безопасность использования

Эта DLL заменяет бинарник игры. Пожалуйста, отнеситесь к этому как к любому
модифицированному игровому модулю:

- **Сделайте резервную копию оригинальной `tier0.dll`** перед установкой
  (`Steam → CS 1.6 → Properties → Installed Files → Verify integrity of game files`
  вернёт файл назад при необходимости);
- **тестируйте на локальных картах/серверах** (`hl.exe -game cstrike -console`,
  `map de_dust2`) перед игрой в онлайне;
- это **не чит и не обход античита**: проект воспроизводит штатное поведение
  оригинальной `tier0.dll` и опубликован как open-source исключительно для
  изучения и модификации движка.

  штатной `tier0.dll` Valve («как у оригинала»);
- **v1.1.0+** — модификация: те же 313 экспортов и совместимость, плюс

  512 МБ с фоновым прекешем страниц, хардненинг lock-free карты слабов

Релиз `v1.0.0` хранит оригинальный артефакт; все последующие релизы в описании
помечаются как модификация. Тег `v1.0.0` даёт доступ к исходникам оригинала
в любой момент. Релизы публикуются на вкладке
**GitHub → Releases** (`https://github.com/V3tR1l1oN/tier0-goldsrc/releases`).

## Внутренние улучшения

Отдельный трек проекта — работа «под капотом», чтобы игра была стабильнее,
ровнее и выдавала честные данные системе (НЕ косметика). К каждому пункту —
выделенная жирным строка «→ в игре», что это даёт игроку.

1. **CPU-инфо** (`cpu.cpp`): количество физических ядер и логических
   потоков теперь считается через `GetLogicalProcessorInformationEx` (у AMD
   раньше выдавало мусор), добавлено определение SSE3/SSSE3/SSE4.1/SSE4.2,
   AVX (только при OSXSAVE) и 3DNow/SSE4A — движок получает корректные флаги
   и может выбирать SIMD-пути.
   **→ в игре:** правильные флаги CPU на всех машинах (особенно AMD); движок не
   старается оглядываться на мусорные значения, SIMD-пути выбираются честно —
   нет «лишних» лагов и просадок, которые проистекали из неверного зондирования.
2. **`Plat_FloatTime`** (`platform.cpp`): предвычисленный множитель
   `1/frequency` вместо деления в каждом кадре + фолбэк при сбое QPC —
   стабильнее frametime и серверная симуляция.
   **→ в игре:** у клиента и сервера общий ровный таймер — интерполяция,
   кадровое время и серверные тики не «плавают»; при сбое счётчика времени
   игра не подвисает, а переходит на резервный источник.
3. **Краш-лог** (`tier0.cpp`): путь извлекается из папки самой `tier0.dll`
   вместо захардкоженного `D:\SteamLibrary\...` — журнал падений пишется на
   любой машине и в любой установке.
   **→ в игре:** если игра упадёт, `crash.log` появляется рядом с DLL на любой
   машине — можно открыть и прислать/прочитать. Раньше на большинстве
   установок лог вообще не создавался, и падения были «слепыми».
4. **`GetSize`** (`mem.cpp`): возвращает реальный размер CRT-блока через
   хэндл кучи CRT (`_get_heap_handle`), а не наугад из process-heap.
   **→ в игре:** движок получает истинный размер буфера, когда читает память;
   не отдаётся мусорное значение — меньше сбоев в логике, опирающейся на
   размер блока (буферы, стримы, считывание валюты NPCT).
5. **Бенчмарк** (`tests/bench.cpp`): объективный замер хот-путей до/после
   правок.
   **→ в игре:** инструмент разработчика; сам по себе на игру напрямую не влияет.
6. **`Realloc(p, 0)`** (`mem.cpp`): по оригиналу память **не освобождается** —
   выделяется блок в 1 байт (дисассем оригинального пула: `mov ebx,1;
   cmovne ebx,edx`). Раньше `realloc(p,0)` делал free и возвращал NULL, что
   давало use-after-free в движке; поведение покрыто регрессионным тестом
   `tests/test_mem.cpp`.
   **→ в игре:** устранён редкий, но очень неприятный класс падений и порчи
   памяти там, где игровой код использует `realloc(…, 0)` — теперь это
   безопасно, как в оригинальной DLL.
7. **`CVProfile::Term`** (`vprof.cpp`): убран двойной `delete` дерева узлов
   при выгрузке DLL (двойное освобождение памяти) — `tests\test_vprof.exe`
   раньше падал на teardown с access violation, теперь завершается чисто.
   **→ в игре:** нет падений при выгрузке DLL и смене больших загружаемых
   модулей — меньше мистических вылетов на перезагрузке карты/CE.
8. **Краш-лог до конца** (`tier0.cpp`): добиты два оставшихся хардкод-участка
   `D:\SteamLibrary\...` (маркеры секций стека) — весь журнал падений без
   исключений пишется рядом с DLL.
   **→ в игре:** как пункт 3 — журнал падений полный на любой установке, вплоть
   до дампа стека, без «слепых зон» из-за хардкод-путей.
9. **Экспорт-харнесс** (`tests/test_exports.cpp`): автосверка всех 313
   экспортов «имя ↔ ординал ↔ адрес» через `GetProcAddress`.
   **→ в игре:** гарантия, что DLL подходит как полная замена оригинальной —
   все 313 функций в точных ординалах. Прямого влияния на геймплей нет,
   влияет на совместимость (игра запускается и работает как с оригиналом).
10. **SBA-ресайклинг** (`mem.cpp`): полностью освобождённые слабы больше не
    копятся мёртвым грузом — уничтожаются, память возвращается CRT-куче и
    переиспользуется новыми выделениями. Меньше фрагментации и пикового
    потребления в долгих сессиях и на серверах.
   **→ в игре:** на длинных матчах и серверах 24/7 процесс не раздувается и не
   дробит память — меньше шансов упереться в лимиты RAM и накопить «мусор»,
   от которого деградирует аллокатор.
11. **Хэш-карта слабов** (`mem.cpp`): поиск владельца блока — цепное
    хеширование по 4K-страницам с проверкой диапазона: O(1) детерминированно,
    без «прочечных бурь». Заодно починена heap-corruption (`0xC0000374`):
    CRT выдаёт слабы с 16-байтным выравниванием, два соседних могут делить
    среднюю страницу — теперь владелец определяется строго по диапазону.
    Квадратичная деградация массовых фри-фаз устранена: `sba_diag 80000 4 2048`
    — с 22.8 s до ~0.25 s; 200 000 итераций — ~0.6 s (раньше не влезало
    и в 300-секундный таймаут).
   **→ в игре:** массовые освобождения (смена карты, спавн-потоки, массовые
   удаления объектов) больше не превращаются в «простой» на секунды — игра
   остаётся отзывчивой; исчез класс падений по heap-corruption (0xC0000374).
12. **Краш-лог расширен** (`tier0.cpp`): помимо `ACCESS_VIOLATION` теперь
    логируются `HEAP_CORRUPTION (0xC0000374)` и `BREAKPOINT (0x80000003)` —
    с полным дампом регистров, EBP-цепи и стека.
   **→ в игре:** если что-то падает, лог говорит больше и точнее — проще найти
   и исправить проблему, в том числе по журналам игроков.
13. **Тесты расширены**: `test_mem` покрывает точное равенство `GetSize`
    округлению (весь 1..2048), кросс-бакетовые `Realloc` 96↔97 и 2048↔2049,
    чурн 4096×50; добавлены многопоточный стресс `test_sba_stress`
    (8–16 потоков, ~5 млн аллокаций) и `test_crash` (проверка журнала
    для 0xC0000374/0x80000003).
   **→ в игре:** регрессионная сетка — каждая следующая правка проверяется от
   этих падений; стабильность не «на глазок», а на тестах.
14. **Хот-путь аллокатора** (`mem.cpp`): предвычисленные таблицы
    `size → bucket` (267 бакетов для ≤2048), `bucket → payload`,
    `bucket → stride` вместо арифметики на каждой операции → слот блоков
    берётся таблично, без делений и веток по диапазонам. Лок переведён на
    `InitializeCriticalSectionAndSpinCount(4000)` — экономный спин перед
    уходом в ядро при контенции.
   **→ в игре:** каждая аллокация/освобождение в движке стала дешевле —
   на фоне сотен тысяч таких операций в секунду это заметно в общей
   отзывчивости и ровности фпс.
15. **Адаптивные слабы** (`mem.cpp`): бакеты, чей блок не влезает в 4096-слаб
    по 2 штуки (payload ≥ 2016 Б, т.е. 2048-байтовые блоки), обслуживаются
    слабами 8192 Б — 3 блока вместо 1. Раньше каждый `Alloc(2048)` карвился
    заново, каждый `Free` — уничтожал слаб (чурн на каждую операцию); теперь —
    одно выделение на три блока. Хэш-карта страниц и `Classify` понимают
    перекрывающиеся несколькими страницами слабы.
   **→ в игре:** блоки 2048 байт (часто используемый размер) больше не рвут
   память каждым выделением/освобождением — меньше фрагментации и лагов на
   кадровых аллокациях, стабильнее фпс в динамичных сценах.
16. **Харнесс контенции** (`tests/test_sba_mt.cpp`): 1/4/16 потоков × чурн
     4..2048 — измеряет стоимость глобального лока и обосновывает решения
     по многопоточности (для одиночного сервера глобальный CS с spin достаточен).
   **→ в игре:** обоснование, что для одиночной игры глобальный лок не помеха —
   дороже контенцию не «лечат» оверкиллом; решение фундаментировано замерами.
17. **Потоковые кэши (TLS) в SBA** (`mem.cpp`): у каждого потока — свой
     кэш «head+count» на бакет; `Alloc` забирает блок из головы без лока,
     `Free` кладёт в голову, а не уничтожает слаб. При переполнении
     (`count > cap`) пачка возвращается в глобал под лок, при refill слабы
     заводятся пачками до 96 блоков. Floor cap для крупных бакетов поднят
     до 16 (мелкие — до 192): чурн-циклы больше не рвут слаб и не гоняют
     malloc/free. Контенция на глобальном локу фактически исчезла.
   **→ в игре:** потоки движка (рендер, сеть, симуляция) почти не контенчат
   аллокатор — многопоточные фазы проходят без буксования, ровнее фпс на
   слабых CPU и в загруженных сценах.
18. **Слаб-арена с фоновым прекешем страниц** (`mem.cpp`): вся память слабов
     живёт в одной большой арене (`VirtualAlloc`-резерв, 512 МБ по умолчанию,
     `SBA_ARENA_MB`/`SBA_RESERVE_MB`/`SBA_ARENA=0`). Фоновый поток
     (`SBA_PREPAGE=0`, чтобы выключить) заранее коммитит и «трогает» страницы
     вперёд от фронта выдачи — загрузка карт с десятками тысяч слабов больше
     не платит страничные фолты на каждом выделении. Прогрев пачками по 1 МБ
     на BELOW_NORMAL-приоритете; если движок аллоцирует быстрее, чем греется
     фронт, цель прогрева адаптивно поднимается, чтобы тёплые страницы
     оставались впереди всплеска (загрузка/спавн). Разрушенные слабы
     ресайклятся (4K/8K) вместо возврата в Windows; при исчерпании арены —
     честный fallback на CRT. Первый проход аллокации 2048-блоков (89 МБ
     слабов): 120 нс/op вместо 1008 нс/op без арены.
   **→ в игре:** загрузка карт и резкие всплески аллокаций (старт раунда,
   длинная прорисовка) быстрее — страничные фолты платятся фоном заранее,
   а не на каждом выделении; «колдовка» при загрузке крупных уровней
   сокращается.
19. **Безопасность lock-free чтения `SBASlabMap`** (`mem.cpp`): горячий
     путь `GetSize`/`Classify` хеширует страницу БЕЗ лока. Grow-гонка (смена
     и `free` прежней таблицы) давала редкий ACCESS_VIOLATION в стресс-тесте.
     Теперь таблица публикуется в порядке `tab → mask → cap`, retired-таблицы
     и узлы НЕ возвращаются в Windows (расход ограничен пиковой нагрузкой),
     обход цепи ограничен — устаревший ход может лишь промахнуться (уйдёт в
     линейный поиск под локом), но не упасть. 15/15 прогонов
     `test_sba_mt 6000000` — чисто (раньше падало ~в 1/3).
   **→ в игре:** устранён редкий, но злой падений в аллокаторе под нагрузкой —
   на серверах 24/7 и длинных матчах меньше «случайных» вылетов в момент
   активной игры.
20. **Threadtools** (`threadtools.cpp`): `CThreadFastMutex::Lock` —
     64×`_mm_pause` перед `Sleep(0)` (нет размена квантов при коротких
     ожиданиях); `CreateSimpleThread` — утечка `pInitData` и висящий
     `*pOutThreadId` при фейле `_beginthreadex`.
   **→ в игре:** короткие ожидания потоков не обмениваются квантами ОС — меньше
   переключений контекста, ровнее тайминги фоновых задач; при частом
   создании потоков нет тихой утечки памяти и висящих id.
21. **Аудит UAF/утечек** (`assert_dialog.cpp`, `vprof.cpp`): удаление
     записи из списка «игнорируемых ассертов» больше не идёт по
     освобождённой памяти (deleted-узел шагает вперёд ДО `delete`,
     голова списка обновляется корректно); у `CVProfNode` при неудачном
     `malloc` имени узел больше не остаётся с мусорным `m_pszName`
     (деструктор звал `free` по мусору). Вся свита и MT-стресс зелёные.
   **→ в игре:** закрыты два потенциальных источника порчи кучи — меньше шансов
   мистических падений из-за запорченной памяти в долгих сессиях.
22. **Помощники платформы без глобального лока** (`exports_fillins.cpp`):
   `Plat_Alloc`/`Plat_Free`/`Plat_Realloc` шли через общий `CThreadMutex` на
   каждый вызов (наследие оригинала, где за локом стоял сырой CRT-heap).
   Сейчас `g_pMemAlloc` уже thread-safe сам по себе (поточные TLS-кэши
   lock-free на горячем пути), так что внешний лок только сериализовал все
   потоки зря — его убрали, путь остался ровно через `g_pMemAlloc`.
   **→ в игре:** движковые потоки, пользующиеся `Plat_*` напрямую (спавн,
   сеть, симуляция), больше не стоят в очереди за одним локом — меньше
   простоев на многопоточных операциях.
23. **`crash.log` больше не растёт бесконечно** (`tier0.cpp`): после 8 МБ
   старый лог переименовывается в `crash_prev.log` (хранится как «прошлое
   падение», при следующей ротации затирается). Долгие игры с частыми
   падениями больше не раздувают файл до сотен МБ.
   **→ в игре:** на диске всегда свежий `crash.log` неограниченного времени
   работы, старый стек падения не теряется.
24. **Настоящий дамп при падении по запросу**: по env `TIER0_MD=1`
   векторное прерывание (access violation / heap corruption / breakpoint)
   вместо простого `crash.log` дополнительно пишет полный `.mdmp`
   (`MiniDumpWriteDump`, с реальными регистрами падения), рядом с `hl.exe`.
   По умолчанию выключено — игровой режим остаётся лёгким; `TIER0_MD=1`
   включается только для разбора конкретного падения.
   **→ в игре:** при необходимости — мгновенный дамп без лишних накладных
   расходов в обычной игре.
25. **GetSize крупных блоков замерян и взят под регрессию**: bench штампует
   стоимость `GetSize` на живых блоках 8192/65536 (≈19/7 нс — проход через
   CRT-heap дешёвый, хедер-кэша не требуется); `test_getsize2048` теперь
   проверяет точный `GetSize` на 20480 и 65536, включая `Realloc` между
   крупными и SBA-2048 в обе стороны (224 и 65536 могут переезжать в памяти).
   **→ в игре:** документированный факт: `GetSize` не упирается в лок даже
   для больших сущностных буферов; пути крупных `Realloc` подтверждены тестом.
26. **CI: crash-smoke и починенный путь сборки тестов** (`build_tests.bat`
   собирался `tests\tests\...` из-за `%~dp0tests` — вычислял папку не от места
   скрипта, а от корня; исправлен на `%~dp0`). В workflow добавлен шаг: запуск
   падающего `test_crash`, требование `=== CRASH ===` в `crash.log` и наличие
   `.mdmp` при `TIER0_MD=1`, всё после прогона чистится.
   **→ в игре:** оборачиваемое в CI — ротация лога и дамп не сломаются
   внезапно при будущих правках.
27. **Защита `vprof` от калибровочного нуля** (`vprof.cpp`): `MarkFrame`
   делил на `g_dwClockSpeed` — если профилирование включалось раньше
   калибровки часов, время кадра улетало в `Inf` и навечно застревало в
   `m_flPeakFrameTime` (мусор в отчёте/графике фпс). Теперь перед делением
   `InitFastTimer()` докалибрует часы.
   **→ в игре:** профилирование (в т.ч. `net_graph`/вотчдоги фпс) не
   покажет разовый бесконечный спайк на раннем старте.
28. **Бенч стабильности часов** (`bench.cpp`): `Plat_FloatTime` — источник
   frametime: измеряем разрывы между соседними отсчётами в чистом прогоне и
   под шумом (поток-аллокатор 256 Б). На Windows QPC сам по себе даёт
   редкие гэпы до ~140 мкс (0.006% отсчётов >1 мкс чисто; ~0.07% под боем).
   Это пол «рывков» от таймера — он в 10-100 раз меньше типичного кадра
   5-15 мс, т.е. источник frametime сам по себе рывков не создаёт.
   **→ в игре:** документированный факт: клиентские рывки по таймеру не
   объясняются (пол в разы меньше) — чинить надо интерполяцию/сеть, а не
   местные часы.
29. **Точный сон для шагов симуляции** (`threadtools.cpp`): `ThreadSleep`/
   `CThread::Sleep` шли на голый `::Sleep()` с квантом системного таймера
   ~15.6 мс. Для 100/128-тикрейтовых серверов это означало: просили спать
   10/7.8 мс — просыпались через ~15 мс, тикрейт схлопывался к ~64, часы
   симуляции отставали от мира → растянутая/дёрганая интерполяция на
   клиентах. Теперь: `timeBeginPeriod(1)` (разово, стандарт для игр) +
   `::Sleep` почти всего интервала + спин последней ~1 мс по QPC с `pause`.
   Получается 10.0±0.2 мс. Legacy-поведение — `TIER0_PRECISE_SLEEP=0`.
   **→ в игре:** серверный тик идёт ровно (без долгих ранних/поздних срабатываний),
   клиентские дельты предсказания и интерполяции не «плывут»;
   бенч ниже показывает разницу в 2 раза по среднему и с нулём медленных тиков из 64.
30. **Бенч pacing тиков** (`bench.cpp`): шлём виртуальный серверный кадр
   (10 мс и 7 мс) и меряем реальные интервалы пробуждения сонтанного потока.
   До: avg 15.0 / 14.6 мс, 63/64 медленных тиков. После: avg 10.02 / 7.00 мс,
   0/64 выше порога. Замер сидит в `bench --smoke`, так что регрессия
   точности сна ловится в CI.

## Как убедиться, что всё соответствует оригиналу

Экспорты и ординалы сверяются `dumpbin` (входит в Build Tools):

```
dumpbin /EXPORTS build\tier0.dll
```

Контрольная сверка всех 313 имён против оригинала даёт **100% совпадение**
(номер 1 ↔ экспорт 1, …, 313 ↔ 313). Это результат сборки из коробки.
Автоматическая проверка — `tests\test_exports.exe`: имя ↔ ординал ↔ адрес
для каждого экспорта из `tier0.def` (см. `tests/README.md`).

## Принципы реконструкции

1. **Карта экспортов** — все 313 функций в точном порядке оригинальных
   ординалов (`tier0.def`) + `__thiscall`/`__cdecl` протоколы как у оригинала.
2. **Декодирование прототипов** — каждый экспорт разобран из дизассемблера:
   имя, `this`, аргументы, возврат; для классов сверена раскладка полей.
3. **Поведение, а не байтовый слепок** — весь код написан вручную на
   современном C++ с идентичным поведением. Оригинал 2024 года собран Valve
   тоже современным MSVC (в импортах видны символы UCRT: `__acrt_iob_func`,
   `__stdio_common_vfprintf` и т.п.), поэтому различия байтов — лишь следствие
   поколений компилятора и раскладки данных.
4. **Специфические куски** — один ассемблерный фрагмент воспроизведён дословно
   (`fdumped_asm_exact.asm`); глобальные данные инициализируются нулём, как в
   оригинале.

Известные ограничения (намеренно повторяют оригинал):

- `DefaultSpewFunc` печатает в `stdout` и возвращает `ASSERT→CONTINUE`,
  `ERROR→ABORT`, прочее → `DEBUGGER`;
- путь Intel VTune/PME не активен (потребители его не вызывают);
- валидатор указателей работает только при `DBGFLAG_VALIDATE`.

## Слово автора

Counter-Strike 1.6 — это больше, чем игра. Для тех, кто вырос в эпоху
интернет-клубов и ночных серверов, это голос эпохи: dust2 на рассвете, звяканье
радио-команд, «rush B, не тормози». И этой легенде хочется служить — честно и
по-настоящему.

Эта DLL — именно про это. Все **313 функций** `tier0.dll` переписаны с нуля
вручную, строчка за строчкой, по дизассемблеру оригинала. Никаких «чёрных
ящиков» Valve, никаких левых сборок и испорченных клиентов: перед тобой
полностью открытый фундамент движка. Его можно читать, изучать, править.

Что это даёт твоей родной CS 1.6:

- **стабильность** — движок на этом низком уровне работает предсказуемо, без
  странных падений, с которыми приходилось мириться годами;
- **честную базу** — весь нижний слой движка прозрачен и понятен, от менеджера
  памяти до профилировщика; если где-то прятался баг этого уровня — его
  теперь реально найти и вычистить;
- **возможность сделать игру лучше без всяких сторонних клиентов**: правь
  загрузку, ресурсы, потоки — всё это начинается именно отсюда, из этого
  кода. Одна DLL, которую ты полностью контролируешь, вместо чужих билдов
  и «улучшайзеров».

Это мой вклад в самую любимую игру моего поколения. Сделано с любовью к CS 1.6
и с верой в то, что у легенды всё ещё впереди.
