# tier0.dll — реконструкция системной DLL движка GoldSrc

> **Это репозиторий-модификация.** Здесь лежит улучшенная сборка `tier0.dll`:
> полностью совместимая с оригиналом (313/313 экспортов, те же ординалы),
> но с работой «под капотом» (см. раздел «Внутренние улучшения»).
>
> Скачивайте осознанно:
>
> - **нужна версия как у оригинала** — берите релиз **v1.0.0** (тег `v1.0.0`);
> - **нужна улучшенная модификация** — берите последний релиз (v1.1.0+).

Функциональная реконструкция `tier0.dll` из движка **GoldSrc**, написанная
с нуля по дизассемблеру оригинальной сборки и собранная на современном MSVC.

DLL воспроизводит **все 313 экспортов оригинала с точными ординалами (1–313)**
и имеет тот же image base (`0x10000000`). `tier0.dll` — низший уровень системы:
её используют `chromehtml.dll`, `vstdlib.dll`, движок и моды. Без неё игра
не запускается.

---

## Для каких игр

- **Counter-Strike 1.6** — `hl.exe -game cstrike`
- **Half-Life** — `hl.exe`
- **Day of Defeat** — `hl.exe -game dod`
- **Team Fortress Classic** — `hl.exe -game tfc`
- любые моды на GoldSrc

Требуется **32-битный Steam-клиент**: Steam, по умолчанию, ставит его при
установке этих игр (совместимость с SteamPipe/SteamPipe-only окружениями — как
у оригинала).

## С какого билда снят оригинал

Оригинал взят из текущей Steam-установки **Counter-Strike 1.6** — это
**последний официальный билд движка**:

- движок: билд **10210** («25th Anniversary Update»), строка `Exe build:
  19:06:31 Oct 7 2024`;
- протокол **48**, `hl.exe` 1.1.1.1;
- эталонный `tier0.dll`: `TimeDateStamp 2024-10-08 01:54:33 UTC`;
- бинари движка не перекомпилировались с октября 2024 (анонсирован был апдейт
  декабря 2023, билд же 10210 Valve выложил молча, без новостного поста).

## Структура проекта

```
tier0/
├── build.bat            Сборка DLL (авто-детект toolchain)
├── tier0.def            Файл экспортов: 313 имён в порядке ординалов 1..313
├── tier0/               Исходники библиотеки (C++ + один .asm)
│   ├── tier0.cpp        Точка входа, стек-трейсы, обработчики FPU/катастроф
│   ├── dbg.cpp          Spew-система, ассерты, валидация указателей
│   ├── mem.cpp          IMemAlloc / менеджер памяти
│   ├── threadtools.cpp  Потоки, события, мьютексы, worker-пул
│   ├── vprof.cpp        Профилировщик (дерево узлов, бюджет-группы)
│   ├── cpu.cpp          Определение CPU (CPUID: MMX/SSE/SSE2/SSE3/AVX, ядра)
│   ├── platform.cpp     Платформозависимые функции (Plat_*)
│   ├── minidump.cpp     Создание .mdmp при крашах
│   ├── ...              Остальные модули (validator, valobject, shims...)
│   └── fdumped_asm_exact.asm  Ассемблерный фрагмент, дословно воспроизведённый по оригиналу
├── tests/              Функциональные проверки DLL (vprof-харнесс, allocator-тест, бенч хот-путей, сверка 313 экспортов — см. tests/README.md)
└── public/tier0/        Публичные заголовки (dbg.h, threadtools.h, vprof.h, ...)
```

Сборка выдаёт единственный артефакт — `build/tier0.dll` (~64 КБ).

## Сборка

### Требования

- Windows x64 или x86;
- **Visual Studio Build Tools** (или полная VS) с компонентом
  «Desktop development with C++», включая инструменты сборки **x86**;
- достаточно любой свежей версии: 2019, 2022 и новее. Собиралось и проверялось
  на: **VS 18 Build Tools**, **MSVC 14.51.36231** (v143), **Windows SDK
  10.0.26100**;
- ничего стороннего (CMake, Qt и т.п.) не нужно.

### Проще всего

```
build.bat
```

Скрипт сам находит `vcvars32.bat` (пробует VS 18 → 2022 → 2019), настраивает
окружение и собирает DLL. Результат:

```
BUILD OK: ...\build\tier0.dll
```

Если уже открыт «x86 Native Tools Command Prompt», скрипт использует его
окружение и не ищет toolchain заново.

### Что делает `build.bat`

1. определение toolchain (`VCToolsInstallDir` либо поиск `vcvars32.bat`);
2. сборка `fdumped_asm_exact.asm` через `ml`;
3. компиляция всех `tier0\*.cpp` через `cl` (x86);
4. линковка: `link /DLL /DEF:tier0.def /BASE:0x10000000 /MACHINE:X86`
   (библиотеки: kernel32, user32, advapi32, dbghelp, odbc32).

## Установка

Положить `build\tier0.dll` рядом с `hl.exe`, например:

```
D:\SteamLibrary\steamapps\common\Half-Life\tier0.dll
```

На `Linux` — `build/tier0.so` рядом с `hlds_linux`/`hlds_run` (там где лежит оригинальный `tier0.so`):

```
~/hlds_l/cstrike/tier0.so  # или рядом с hlds_linux
```

`Linux` сборка — полный `1:1` аналог `Windows` `tier0.dll` (тот же `316` экспортов, `mmap` вместо `VirtualAlloc`, `pthread` вместо `Win32` тредов) — можно кидать также, будет работать лучше/стабильнее чем оригинал (меньше фризов, ровный тик).

Проверено на CS 1.6: `hl.exe -game cstrike` загружается и работает стабильно,
`crash.log` не создаётся, профилирование `-vprof` работает. Дополнительно
прогнан смоук на Dedicated Server (`hlds.exe`, билд 10210, `cstrike` 1.1.2.7):
сервер поднимается и работает с этой DLL без крашей; полный игровой прогон
описан в истории релизов.

## Важно: безопасность использования

Эта DLL заменяет бинарник игры. Пожалуйста, отнеситесь к этому как к любому
модифицированному игровому модулю:

- **Сделайте резервную копию оригинальной `tier0.dll`** перед установкой
  (`Steam → CS 1.6 → Properties → Installed Files → Verify integrity of game files`
  вернёт файл назад при необходимости);
- **тестируйте на локальных картах/серверах** (`hl.exe -game cstrike -console`,
  `map de_dust2`) перед игрой в онлайне;
- это **не чит и не обход античита**: проект воспроизводит штатное поведение
  оригинальной `tier0.dll` и опубликован как open-source исключительно для
  изучения и модификации движка.

## Версии

- **v1.0.0** — оригинальная публикация: реконструкция, повторяющая поведение
  штатной `tier0.dll` Valve («как у оригинала»);
- **v1.1.0+** — модификация: те же 313 экспортов и совместимость, плюс
  внутренние улучшения (раздел ниже);
- **v1.2.0** — фикс двойного `free` в `CVProfile::Term` при выгрузке, доводка
  журнала крашей;
- **v1.3.0** — TLS-кэши аллокатора (lock-free alloc/free), слаб-арена
  512 МБ с фоновым прекешем страниц, хардненинг lock-free карты слабов
  (фикс редкого MT ACCESS_VIOLATION), фиксы threadtools и аудит UAF.
- **v1.4.0** — точный тик-пейсинг под боевой нагрузкой (precise sleep:
  timeBeginPeriod + QPC-спин, 100-тик = 10.02 мс avg, 0 медленных из 64),
  честная детекция CPU с учётом affinity (12/6 вместо 12/12), benchmark,
  CI (test_cpu + test_cpu 4), журнал крашей crash.log/.mdmp, стресс-тест
  аллокатора, аудит-фиксы: spew-группы (дубликаты/переполнение),
  heapchk=_HEAPOK, bounded-таймаут fast-mutex, баланс vprof Start/Stop,
  IgnoreAssertsNearby, кольцевой scratch, закрытие хендла потока.
- **v1.5.0** — синхронизация односекционного `CWorkerThread` call-slot:
  атомарное резервирование запроса, корректная публикация параметров,
  защита completion event от устаревшего сигнала и освобождение слота только
  после `Reply`; исправлена семантика параметраless `CThreadFastMutex::Lock`
  (ожидание бесконечное, как ожидает ABI). Добавлена строгая валидация
  `WaitForMultipleEvents`, потокобезопасная инициализация QPC/CPU-информации,
  проверка поддерживаемых CPUID-листьев, affinity-aware fallback для topology,
  защита crash-handler от повторного входа и проверка читаемости памяти при
  обходе стека. Добавлены `test_threadtools` и расширен CI fallback/crash smoke.
- **v1.6.0** — безопасное завершение слаб-арены и fail-closed жизненный цикл
  потоков: `SBArena_Stop()` джойнит фоновый pre-page поток *до* освобождения
  slab-подложки (закрыт use-after-free), жизненный цикл арены — конечный
  автомат с wake-событием, при невозможном join — намеренный leak вместо
  разгрузки живой памяти. `CThread::Join` fail-closed на `WAIT_FAILED`,
  `Stop()` трактует отрицательный таймаут как бесконечный, `Terminate()`
  не убивает вызывающий поток и держит handle в собственности до `Join`/dtor,
  `CWorkerThread::Call` при таймауте ответа завершает worker с ошибкой
  (`TIER0_WORKER_TIMEOUT_MS`, по умолчанию 30 с). CI полностью зелёный:
  починен regex проверки 313 экспортов, crash-smoke переведён на BREAKPOINT
  и сброс `$LASTEXITCODE` после намеренного краша — все 12 шагов проходят.
- **v1.6.1** — выпуск документации: в тег перенесены README-раздел v1.6.0 и

  сборка `tier0.dll`).
- **v1.6.2** — улучшение устойчивости (менее крупный внутренний пункт,

## Внутренние улучшения

Отдельный трек проекта — работа «под капотом», чтобы игра была стабильнее, ровнее и выдавала честные данные системе (НЕ косметика). К каждому пункту — выделенная жирным строка «→ в игре», что это даёт обычному игроку простыми словами.

1. **CPU-инфо** (`cpu.cpp`): игра теперь правильно определяет процессор через `GetLogicalProcessorInformationEx`. Раньше на `AMD` показывало бред (12 ядер вместо 6), и движок включал не те оптимизации. Добавили проверку `SSE3/SSSE3/SSE4.1/SSE4.2/AVX/3DNow` только если система их реально поддерживает.
   **→ в игре:** на любом ПК, особенно на `AMD Ryzen`, игра видит твой реальный процессор и включает правильные ускорения. Нет лишних лагов из-за того что движок думал что у тебя "не тот" CPU и пытался гнать код не тем путём.

2. **`Plat_FloatTime`** (`platform.cpp`): раньше каждый кадр делили на частоту таймера, теперь считаем `1/frequency` один раз и умножаем. Если кварцевый таймер `QPC` вдруг сбоит — есть запасной монотонный таймер.
   **→ в игре:** время кадра и тики сервера идут ровно, как метроном. Картинка не дёргается, а если часы сбоят — игра не зависает, а тихо переходит на резерв.

3. **Краш-лог** (`tier0.cpp`): раньше путь к логу был вшит `D:\SteamLibrary\...` и на 99% ПК файл просто не создавался. Теперь берём папку где лежит сама `tier0.dll`.
   **→ в игре:** если игра упала — рядом с `tier0.dll` всегда появится `crash.log`. Ты можешь его открыть, прочитать или скинуть другу/админу. Раньше падения были "слепыми" — лога просто не было.

4. **`GetSize`** (`mem.cpp`): спрашиваем размер блока у своей кучи `_get_heap_handle`, а не наугад у общей кучи `Windows`.
   **→ в игре:** когда движок спрашивает "сколько памяти в этом блоке?" — получает честный ответ, а не случайное число. Меньше глюков с инвентарём, буферами и сохранениями.

5. **Бенчмарк** (`bench.cpp`): просто линейка — меряет скорость аллокатора до и после правок.
   **→ в игре:** на игру не влияет, это для нас — чтобы не гадать, а цифрами видеть что стало быстрее.

6. **`Realloc(p,0)`** (`mem.cpp`): по оригиналу `realloc` с нулём не должен освобождать память, а дать 1 байт. Мы так и сделали. Раньше он делал `free` и возвращал `NULL`, а движок потом писал в освобождённую память и падал.
   **→ в игре:** убрали редкие, но очень обидные вылеты с порчей памяти, когда код игры делал `realloc(...,0)`. Теперь это безопасно как в оригинале.

7. **`CVProfile::Term`** (`vprof.cpp`): при выгрузке `DLL` дерево профайлера удалялось дважды — двойное освобождение памяти.
   **→ в игре:** нет вылета при выходе с карты или перезагрузке `DLL` — раньше именно тут ловили `access violation` на `Term`.

8. **Краш-лог до конца** (`tier0.cpp`): добили два оставшихся вшитых пути `D:\SteamLibrary\...` в дампе стека.
   **→ в игре:** лог теперь полный на любом диске `C:`, `D:`, `E:` — вплоть до стека вызовов, без дыр.

9. **Экспорт-харнесс** (`test_exports.cpp`): автоматом сверяем все 316 экспортов `имя ↔ ординал ↔ адрес`.
   **→ в игре:** гарантия что наша `DLL` — полная замена оригинала. Игра запустится с ней как с родной, без "не найдена функция".

10. **SBA-ресайклинг** (`mem.cpp`): пустые слабы (куски памяти на 4К/8К) раньше копились мёртвым грузом. Теперь уничтожаем и отдаём память обратно.
    **→ в игре:** за 3 часа игры или на сервере `24/7` процесс не раздувается в оперативке. Нет "утекания" памяти когда долго играешь.

11. **Хэш-карта слабов** (`mem.cpp`): поиск "кто владелец блока" теперь за `O(1)` через хеш по страницам, а не перебором. Починили `heap-corruption 0xC0000374` когда два блока делили одну страницу. Было 22 секунды на 80к блоков → стало 0.25с.
    **→ в игре:** смена карты, спавн толпы ботов, массовое удаление объектов больше не фризит на секунды. Игра остаётся отзывчивой, пропал целый класс вылетов `0xC0000374`.

12. **Краш-лог расширен** (`tier0.cpp`): ловим не только `ACCESS_VIOLATION`, но и `HEAP_CORRUPTION`/`BREAKPOINT` с регистрами и стеком.
    **→ в игре:** если что-то упало — в логе теперь видно причину, а не "упало и всё". Проще найти виновника по логам игроков.

13. **Тесты расширены**: проверяем `GetSize` на всех размерах 1..2048, `Realloc` 96↔97, стресс 5 млн аллокаций на 16 потоках.
    **→ в игре:** каждая правка прогоняется через решето тестов — стабильность не "на глаз", а на цифрах. Новая фича не сломает старую тихо.

14. **Хот-путь** (`mem.cpp`): таблицы `size→bucket` заранее посчитаны, спин `4000` перед уходом в ядро.
    **→ в игре:** каждое `Alloc`/`Free` (а их сотни тысяч в секунду) стало дешевле — в сумме `FPS` ровнее, меньше микрофризов.

15. **Адаптивные слабы** (`mem.cpp`): 2048-байтовые блоки теперь живут в слабах 8К по 3 штуки, а не по 1. Раньше каждый `Alloc(2048)` создавал новый слаб, каждый `Free` — убивал.
    **→ в игре:** частый размер 2048 (модели, звуки) больше не рвёт память. В замесах с гранатами/дымами меньше лагов.

16. **Харнесс контенции** (`test_sba_mt.cpp`): меряем 1/4/16 потоков.
    **→ в игре:** доказали что одного лока со спином хватает для обычной игры — не городим оверхед.

17. **Потоковые кэши TLS** (`mem.cpp`): у каждого потока свой кэшик `head+count` на каждый размер. `Alloc` берёт из головы без лока, `Free` кладёт туда же.
    **→ в игре:** рендер, сеть и логика не толкаются в одной очереди за память. На слабых `CPU` и в дымах `FPS` не проседает из-за аллокатора.

18. **Слаб-арена 512МБ** (`mem.cpp`): вся память слабов в одном куске 512МБ (настройка `SBA_ARENA_MB`), фоновая нить заранее "трогает" страницы по 1МБ.
    **→ в игре:** карта `de_aztec` или `cs_assault` грузится заметно быстрее — страницы уже тёплые, а не по одной на каждом `Alloc`. Всплеск на старте раунда не фризит.

19. **Lock-free чтение карты** (`mem.cpp`): `GetSize` без лока читает хеш-таблицу, публикация `tab→mask→cap` строго по порядку, старые таблицы не возвращаем в `Windows`.
    **→ в игре:** убрали редкие вылеты под нагрузкой (15/15 прогонов `6M` чисто, раньше падал 1 из 3). На сервере 32 слота меньше случайных крашей в замесе.

20. **Threadtools** (`threadtools.cpp`): `FastMutex` 64×`pause` перед `Sleep`, починили утечку `CreateSimpleThread`.
    **→ в игре:** короткие ожидания не отдают квант `Windows` зря — меньше переключений, тайминги ровнее. Нет тихой утечки при частом создании нитей.

21. **Аудит UAF** (`assert_dialog.cpp`, `vprof.cpp`): починили удаление из списка игнора ассертов и `m_pszName`.
    **→ в игре:** нет порчи кучи в долгих сессиях из-за этих мелочей.

22. **Помощники без лока** (`exports_fillins.cpp`): убрали общий мьютекс из `Plat_Alloc` — `g_pMemAlloc` и так thread-safe.
    **→ в игре:** движковые потоки (спавн, сеть) не стоят в одной очереди за памятью.

23. **Ротация лога** (`tier0.cpp`): после 8МБ `crash.log` → `crash_prev.log` (старый затирается).
    **→ в игре:** даже если игра падает каждый час неделями, лог не вырастет до 500МБ. Всегда есть свежий и предыдущий.

24. **Дамп по запросу** (`tier0.cpp`): `TIER0_MD=1` — пишет `.mdmp` с регистрами рядом с `hl.exe`. По умолчанию выкл.
    **→ в игре:** в обычной игре без накладных, а когда надо поймать баг — включил переменную и получил полный дамп для разбора.

25. **GetSize крупных блоков**: замер `GetSize` 8К/64К (~19/7нс), тест `test_getsize2048`.
    **→ в игре:** большие буферы (модели, звуки) тоже быстро, без лока.

26. **CI** (`build_tests.bat`, `ci.yml`): починили путь `tests\tests\...`, добавили проверку `crash.log`+`.mdmp`.
    **→ в игре:** в `CI` видно что ротация и дамп не сломались в будущем.

27. **Защита vprof** (`vprof.cpp`): перед делением на `g_dwClockSpeed` калибруем часы.
    **→ в игре:** в `net_graph`/профайлере нет бесконечного спайка `FPS` на старте, когда часы ещё не прогрелись.

28. **Стабильность часов** (`bench.cpp`): `Plat_FloatTime` даёт гэпы ~140мкс, 0.006% >1мкс — в 100 раз меньше кадра 5-15мс.
    **→ в игре:** рывки не из-за таймера — его полка в разы ниже кадра, чинить надо сеть/интерп, а не часы.

29. **Точный сон** (`threadtools.cpp`): `timeBeginPeriod(1)` + `Sleep` + спин 1мс по `QPC`. Было 15мс/63 медленных → стало 10.02мс/0.
    **→ в игре:** сервер `100 tick` тикает ровно, как часы. На клиенте интерполяция не растягивается, стрельба не "плывёт".

30. **Бенч pacing** (`bench.cpp`): гоняем 10мс/7мс тики в `bench --smoke`.
    **→ в игре:** если сон снова испортится — `CI` сразу покраснеет.

31. **Отчёт CPU честный** (`cpu.cpp`): топология через `GetLogicalProcessorInformationEx` с учётом `affinity` процесса.
    **→ в игре:** если ты запустил `hl.exe` на 2 ядрах (`start /affinity`), движок не думает что у тебя 12 ядер и не плодит 12 потоков в пуле. Нет лишней толкотни.

32. **Worker-call синхронизирован** (`threadtools.cpp`): слот резервируется атомарно, `completion` сбрасывается перед публикацией.
    **→ в игре:** фоновые задания (загрузка ресурсов) не путают параметры — нет "ответил не тем".

33. **Проверки событий** (`threadtools.cpp`): `WaitForMultipleEvents` проверяет handles, `Lock()` без аргумента ждёт вечно.
    **→ в игре:** меньше скрытых дедлоков из-за кривого вызова.

34. **Старт таймеров потокобезопасен** (`platform.cpp`, `cpu.cpp`): `QPC`/`CPU` инициализация атомарно.
    **→ в игре:** ранний старт с нескольких потоков не видит полуинициал.

35. **Crash-handler безопаснее** (`tier0.cpp`): защита от рекурсии, проверка `MEM_COMMIT` перед чтением `EBP`.
    **→ в игре:** даже при тяжёлом падении больше шанс получить полный `crash.log`+`.mdmp`.

36. **Регрессия расширена** (`test_threadtools.cpp`, `test_regress.cpp`): `ABI`, async вызовы, `VProf` после `Term`, `SBA_ARENA=0`.
    **→ в игре:** новые фиксы прикрыты тестами — следующая правка не сломает тихо.

37. **Безопасное выключение арены** (`mem.cpp`): `hWake` событие + автомат `0/1/2/3`, `Stop` джойнит нить до `free`.
    **→ в игре:** на выходе с карты/сервера нет висящей нити над освобождённой памятью — нет редких вылетов при `changelevel`/`quit`.

38. **Fail-closed потоки** (`threadtools.cpp`): `Join`/`Stop`/`Terminate`/`Call` с таймаутом `30с`.
    **→ в игре:** если фоновый поток завис — игра не виснет навечно, а честно пишет "ошибка" и идёт дальше. Меньше "зависших" серверов.

39. **Тесты shutdown и CI**: `test_sba_shutdown`, `WaitForReply` слот 10, фикс `dumpbin` regex, `BREAKPOINT` + сброс `LASTEXITCODE`.
    **→ в игре:** пути остановки проверены, `CI` честный — 12/12 зелёных не на словах.

40. **Чистая пара таймера** (`threadtools.cpp`/`tier0.cpp`): `timeBeginPeriod(1)` → `timeEndPeriod(1)` в `DLL_PROCESS_DETACH` (CAS 2→4), `TIER0_HIGHRES_TIMER=0` opt-out.
    **→ в игре:** пока игра запущена — тик точный (10/7мс), после выхода `1мс` не остаётся висеть в системе и не жрёт батарею/не будит другие процессы.

41. **Реальная проверка кучи** (`mem.cpp`): `heapchk` через `HeapValidate` → `_HEAPOK` только на здоровой куче, `CrtIsValid*` через `HeapValidate`.
    **→ в игре:** если память побита — игра честно скажет "куча битая", а не промолчит и не упадёт через 5 минут в другом месте.

42. **Защита scratch** (`exports_fillins.cpp`): убран `%SCRATCH_MAX_DEPTH`, 33-й `MemAllocScratch` → `NULL`.
    **→ в игре:** даже если какой-то мод вложил 33 временных буфера — не испортит память, а просто скажет "нет слота".

43. **VEH и краш-хендлер** (`tier0.cpp`): `g_hVeh` снимается, `PIN` проверяется, `SEH` вокруг `EBP`, `uintptr_t`, снапшот один, `WRITE_THROUGH`.
    **→ в игре:** после `FreeLibrary` нет прыжка в выгруженную память, лог не теряет второй краш и не дедлочит в `HeapLock`. Дамп есть даже при `STACK_OVERFLOW`.

44. **Minidump без hijack** (`minidump.cpp`): `SystemDirectory`+`SEARCH_SYSTEM32`, атомарные счётчики, `__try/__finally`, `localtime_s`, `GetEnvironmentVariableA`.
    **→ в игре:** никто не подложит левую `DbgHelp.dll` в папку с картой и не получит `RCE`. Дампы не теряются из-за залипшего лока.

    **→ в игре:** `Msg` из разных потоков не портит имя файла в логе — в консоли видно кто и откуда ругается.

46. **SBA стабильнее** (`mem.cpp`): `overflow` проверка, `g_sbaReady` guard, откат `handout`.
    **→ в игре:** редкий `Free` после выгрузки `DLL` не уронит процесс.

47. **PreciseSleep без зависаний** (`threadtools.cpp`): `GetEnvironmentVariableA`, таймаут 100мс, лимит `target+5мс`.
    **→ в игре:** при скачке времени `NTP` тик не уходит в 100% загрузку ядра.

48. **Синхронизация без копий** (`threadtools.cpp`): `FastMutex` copy → новый, `WaitForMultipleEvents` >64→-1, `Pulse`→`Set`.
    **→ в игре:** нет двойного `Unlock` чужого мьютекса, нет потерянных сигналов.

## Как убедиться, что всё соответствует оригиналу

Экспорты и ординалы сверяются `dumpbin` (входит в Build Tools):

```
dumpbin /EXPORTS build\tier0.dll
```

Контрольная сверка всех 313 имён против оригинала даёт **100% совпадение**
(номер 1 ↔ экспорт 1, …, 313 ↔ 313). Это результат сборки из коробки.
Автоматическая проверка — `tests\test_exports.exe`: имя ↔ ординал ↔ адрес
для каждого экспорта из `tier0.def` (см. `tests/README.md`).

## Принципы реконструкции

1. **Карта экспортов** — все 313 функций в точном порядке оригинальных
   ординалов (`tier0.def`) + `__thiscall`/`__cdecl` протоколы как у оригинала.
2. **Декодирование прототипов** — каждый экспорт разобран из дизассемблера:
   имя, `this`, аргументы, возврат; для классов сверена раскладка полей.
3. **Поведение, а не байтовый слепок** — весь код написан вручную на
   современном C++ с идентичным поведением. Оригинал 2024 года собран Valve
   тоже современным MSVC (в импортах видны символы UCRT: `__acrt_iob_func`,
   `__stdio_common_vfprintf` и т.п.), поэтому различия байтов — лишь следствие
   поколений компилятора и раскладки данных.
4. **Специфические куски** — один ассемблерный фрагмент воспроизведён дословно
   (`fdumped_asm_exact.asm`); глобальные данные инициализируются нулём, как в
   оригинале.

Известные ограничения (намеренно повторяют оригинал):

- `DefaultSpewFunc` печатает в `stdout` и возвращает `ASSERT→CONTINUE`,
  `ERROR→ABORT`, прочее → `DEBUGGER`;
- путь Intel VTune/PME не активен (потребители его не вызывают);
- валидатор указателей работает только при `DBGFLAG_VALIDATE`.

## Слово автора

Counter-Strike 1.6 — это больше, чем игра. Для тех, кто вырос в эпоху
интернет-клубов и ночных серверов, это голос эпохи: dust2 на рассвете, звяканье
радио-команд, «rush B, не тормози». И этой легенде хочется служить — честно и
по-настоящему.

Эта DLL — именно про это. Все **313 функций** `tier0.dll` переписаны с нуля
вручную, строчка за строчкой, по дизассемблеру оригинала. Никаких «чёрных
ящиков» Valve, никаких левых сборок и испорченных клиентов: перед тобой
полностью открытый фундамент движка. Его можно читать, изучать, править.

Что это даёт твоей родной CS 1.6:

- **стабильность** — движок на этом низком уровне работает предсказуемо, без
  странных падений, с которыми приходилось мириться годами;
- **честную базу** — весь нижний слой движка прозрачен и понятен, от менеджера
  памяти до профилировщика; если где-то прятался баг этого уровня — его
  теперь реально найти и вычистить;
- **возможность сделать игру лучше без всяких сторонних клиентов**: правь
  загрузку, ресурсы, потоки — всё это начинается именно отсюда, из этого
  кода. Одна DLL, которую ты полностью контролируешь, вместо чужих билдов
  и «улучшайзеров».

Это мой вклад в самую любимую игру моего поколения. Сделано с любовью к CS 1.6
и с верой в то, что у легенды всё ещё впереди.
